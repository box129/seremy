## Eight-stage scope

| Stage | Implemented scope | Still requires a separate implementation/evaluation profile |
|---|---|---|
| 1 Discovery | Bounded frozen inventory, named exclusions, Git/plain-folder scope, hashes and coverage. | Full plain-folder ignore parity, cross-platform replacement-race qualification and additional script/language extensions. |
| 2 Parsing | Python AST and pinned compiler extraction for TS/JS/JSX/TSX, parse outcomes and source spans. | Arbitrary syntax-region interaction, callable/arrow identities and additional language grammars. A complete parse record is not full semantic coverage. |
| 3 Resolution | Observed direct function calls using TS checker/aliases or Python lexical/module binding; explicit unsupported/missing/non-processed outcomes. | Dynamic dispatch, callable-value/member targets, complex TypeScript project graphs and runtime semantics. |
| 4 Framework evidence | Registered package manifests and separately labelled import evidence. | Framework-specific route, DI, ORM and runtime relationship extraction with independent truth fixtures. |
| 5 Components | Structural baselines plus an opt-in versioned membership contract, authored/candidate adapters, hierarchy/cuts, evidence, unassignment/disputes, roles and whole alternatives. Graph, documentation, map and MCP projections are checked. | A bounded call-core candidate and lineage-aware conformance comparison are exercised. Responsibility-informed grouping, historical truth adjudication and independently reviewed semantic ownership accuracy remain open. [Contract and entry points](membership-views.md). |
| 6 Relationships | Typed observed component aggregation, retained source-site counts, bounded paths/cycles. | Broader semantic relationship kinds. A static path is not an execution trace. |
| 7 Validation | Snapshot/evidence/conservation/policy checks plus post-synthesis template verification. | Independent semantic accuracy, original research acceptance cases and general production acceptance. |
| 8 Documentation | Structured deterministic guide and Markdown from the canonical graph, with post-generation checks and dependency invalidation. | Local MCP draft submission is exercised with a real model/SDK example and adversarial projection checks. Independent free-prose support and usefulness qualification remain open. |
