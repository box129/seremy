# Developer guide generation

Guide v0.4 adds [named callable structure](callable-bindings.md): cited lexical identities, observed outgoing targets, incoming-site counts and file-owner qualifications. Callback/event invocation is explicitly unestablished, and zero incoming calls do not establish unused code. Existing MCP section tools include these claims and their evidence for reviewed drafting.

The deterministic generator creates a repository overview, direct-call walkthroughs, package and directory summaries, framework evidence and coverage limits. Each guide section references structured claims. Walkthroughs include both the recorded call sites and the target declaration. The graph, Markdown and Docs source navigation share the same snapshot binding.

Open Documentation after analysis. Click a call-site or target-declaration link to focus its exact source range in the map. Back restores the previous map location. The Markdown action downloads `architecture.md`. To follow its relative links offline, download the map as `map.html` into the same directory and open it through a browser that supports the map's source verification. Hosted saved reports retain Markdown and its in-app source navigation after server expiry.

The DocumentIR stores section IDs, claim IDs, subjects, witnesses, source citations and graph/stage dependencies. Framework manifest witnesses retain the manifest hash. Structural claims retain the membership version and view target. The complete graph digest includes snapshot, configuration and policy dependencies. Validation reconstructs the deterministic projection and checks the exact claim roster, text, witnesses, citations, section membership and dependencies. A valid citation to an unrelated declaration cannot support a call claim. Changed graph inputs require regenerating and validating the guide. This release conservatively invalidates the entire guide when its bound graph changes.

The publication includes `document-ir.json`, `architecture.md` and `validation.json`. Graph and template validation outcomes appear in the validation report. Publication remains a coverage-limited draft with independent semantic/usefulness review pending. Source text and repository metadata are rendered as text in Docs. Citation navigation checks the active graph digest, source hash and UTF-8 range before focusing.

Verification includes the full Python suite, targeted documentation and JSX checks, Redux guide journeys in SVG and Pixi, standalone Markdown citation navigation, rejection of a foreign graph digest, and launcher/MCP regression journeys. Receipts record the executed revision and scope. Edge qualification uses Chromium; other browser engines retain separate qualification.

The local MCP tools read validated claims and bounded section evidence. [Model-assisted section drafting](documentation-drafts.md) now supports versioned submissions, reported generation metadata, explicit statement checks, citation navigation, downloads and saved-view restoration. A Codex model with an SDK bridge exercised one real draft. Independent free-prose support evaluation and human usefulness scoring remain open. Semantic ownership, business purpose and runtime behavior require additional evidence.
