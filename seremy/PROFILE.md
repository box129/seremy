## Relationship to archdoc-ai

This package is intentionally separate from `backend/app` (the FYP submission).
The [ArchDoc-vs-SEREMY comparison](../outputs/ArchDoc-vs-SEREMY/COMPARISON.md)
found ArchDoc's resolver unsuitable as a source of factual edges; the T1–T5
modules here implement the SEREMY contract from scratch and do not import
archdoc-ai backend code.

## Reproduction after binder takeover

From the repository root run `python -B -m pytest -q -p no:cacheprovider seremy/tests`, then `python -B seremy/tools/build_slice.py`, then `node seremy/tools/check-map.cjs seremy/map`. Playwright needs its installed Chromium browser, or CHROME_BIN pointing to an installed compatible executable.

The generator reads map/template.html and writes map/map.html. Repeated builds keep identical artifact bytes for unchanged source and paths. The current sample parses two of the 17 inventoried TypeScript files. Its one call edge is independently checked against source bytes. The sample document retains explicit partial coverage and pending publication validation.

The takeover suite passed 84 Python tests. Six browser checks passed for source binding, geometry, follow/back, provenance, collapse/expand and stale-embedding rejection. These are scoped slice results. Production graph coverage, general TypeScript constructs, framework/component stages, map performance, publication recovery and full product acceptance remain open. See artifacts/m1-takeover-receipt.json. Earlier m1-t0-t8 assertions describe the superseded Python heuristic binder.
